# 0.1.0-pre.7 — Controller diagnostics and transport lifecycle

This prerelease retains the self-contained Windows launcher, standard-user
storage fallback, shared window icons/favicon, graphics backend and pre.6 save /
window corrections. Supply your own valid game files; original data is excluded.

- Reused network clients start with clean connection state; old closes cannot
  cancel new readers. Live/pending duplicate connects and failed handshakes have
  explicit lifecycle checks.
- Source transport protocol 2 supports host-controlled return to lobby with a
  matching session ID, fresh readiness and isolated input timelines. Delayed old
  input or stop commands cannot affect a new round. Both server and client must
  be updated. This component is in the source package; the launcher still does
  not provide playable online matches or a synchronized engine adapter.
- Explicit private diagnostic input permits isolated virtual-pad acceptance;
  normal input still requires foreground ownership. Disabling or invalidating
  that packet restores focus rejection and neutral input.
- Added localized 3D stencil-shadow coverage beyond both former 4:3 boundaries,
  preserving unmarked pixels, producer vertices and stencil/color-write states.

## Recorded acceptance

The preceding source passes 135 Python tests with one Windows privilege skip,
21 named native CPU checks and 28 GPU/input/import cases. Four virtual pads are
assigned two per team in the real game. Selected windowed gameplay/replay and
natural introduction transitions recover after resize/minimize/restore, then
close cleanly with copied saves unchanged. Physical SDL discovery is bypassed
by the private four-pad producer; physical hardware is not accepted by that test.
Final archive/build checks are recorded separately in the work board.

Input-cache and random-state traces distinguish verified ownership from pending
synchronization work. Per-update reseeding is not proof of matching complete
simulation state across processes.
