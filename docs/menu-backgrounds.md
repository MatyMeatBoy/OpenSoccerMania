# Native menu backgrounds and controller buttons

The supported executable draws both the pause backdrop and `Loading_FromTitle` through the native `BrickBackdrop` renderer at `0x52f3d0`. Its sprite call returns at `0x52f45e` and emits an 80-cell grid of 64-unit tiles. The resources are the original loaded `Brick` / `Brick_Flat` sprites; no original game artwork is included in this project.

`menu_background.h` captures only this producer's complete 10-by-8 grid with its original full 640-by-480 clip. After flushing the original batch, it repeats the source cells into the side areas, keeping the original center untouched. Each cell retains the native final vertex colors, UVs, tile size, row phase and engine XY offsets. The replay uses the current original 2D shader and the bridge's ordinary HUD projection adjustment. Non-overlapping cells are batched by their original loaded texture. The native clip is never enlarged: its setter also changes the engine viewport, so changing it would affect unrelated drawing.

The replay requires a verified supported executable and exact instruction signatures, the physical backbuffer, the complete grid, ordinary axis-aligned cell geometry and dedicated 64-by-64 source textures. A full D3D8 state block restores the source stream, texture, shader and render state. Other menus, videos and render targets do not acquire a general texture-stretch rule.

The original footer buttons are dedicated 64-by-64 sprites with UVs `(0,0)..(1,1)`. Their exact call return addresses are `0x4f72d1` for Back (original numeric 2 at x16,y384) and `0x4f7327` for Select (numeric 1 at x560,y384). With an attached controller and `Graphics.XboxPrompts=1`, only these calls temporarily swap the original stage-zero texture for a generated red B or green A. The original geometry, native fades, screen locations and HUD transform are retained. The batch is flushed before and after the scoped swap. Texture creation failure, an unexpected atlas size or disabled prompts leaves the original art available; no generic legend is added.

`tests/native_menu_background.cpp` checks the exact 16:9 and ultrawide cell plans, source immutability, invalid-grid rejection, exact footer contexts and generated glyph content. `tests/native_menu_background_render.cpp` is an asset-free isolated GPU consumer check. It uses the production helper and bridge to compare the center pixel-for-pixel before/after, checks sidebar color/phase continuity and restores stream/texture state. It also verifies the scoped 64-by-64 prompt swap and a 128-by-128 atlas fallback. These synthetic checks pass with the official bundled backend. An isolated real-game run also confirmed the exact native 80-cell producer and 32 added cells at 16:9. Its loading-screen capture shows the checker reaching both outer edges at the native cell size; the main-menu capture shows red B and green A in the original footer locations. The runtime logs confirm 64-by-64 source textures, UVs `(0,0)..(1,1)` and successful scoped swaps. Pause-screen visual acceptance is recorded separately in the private evidence.
