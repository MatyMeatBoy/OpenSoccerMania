# OpenSoccerMania implementation plan

Historical planning record. Checkboxes reflect the initial plan, not current acceptance. See the work board and release notes for current evidence.

Goal: a local English desktop launcher accepting ISO images, extracted discs and installed games; reversible compatibility work on private copies.

Architecture: Python/Tkinter/Pillow, matching the rounded material language of NewSnapRecomp with original football artwork. Separate source discovery, import, binary inspection, guarded patches, video configuration and UI. No account or server. Original game data excluded from Git.

User direction: continue directly with improvements, use NewSnapRecomp as visual reference, English throughout, up to 4K and 240 Hz, preserve simulation, support correct wide/ultrawide aspect ratios.

Chosen approach: incremental x86 compatibility/mods, then motor reconstruction. Full decompilation delays the playable milestone; automatic x86 recompilation remains experimental. The requested continuation selects the incremental approach proposed in the reconnaissance.

- [ ] Source detection tests: installed game, extracted installer tree, zero-filled executable, missing assets and case-insensitive paths.
- [ ] Implement discovery and private transactional import. ISO mounts are read-only and always detached when this process mounted them. Never run installers or write to source.
- [ ] Analyze the two PE files and compare changed code; identify actual startup checks before authoring guarded patches.
- [ ] Add tested patch manifests with exact hash and original-byte checks. Unsupported versions fail closed. Never patch clock/physics functions to force FPS.
- [ ] Video profiles: up to 3840x2160 and wide/ultrawide monitor modes through 240 Hz; aspect-preserving presentation as fallback. True Hor+ and render FPS remain explicit pending capabilities until implemented and measured.
- [ ] Rounded textured English launcher with import, library state, play, video and diagnostics, persistent local settings, background I/O and recoverable errors.
- [ ] Run unit/integration tests on fixtures and available dumps. Capture and inspect the actual window; package a standalone Windows launcher.

Review focus: paths with spaces; damaged/zero binaries; import failure and cleanup; unsupported executable hashes; simulation invariance vs display refresh; partial installations; source copies staying unchanged.

Ruling: preserve an honest capability boundary: never label output resolution or monitor Hz as a proven gameplay FPS or Hor+ patch. User originals may already be modified; hash identity is essential.
